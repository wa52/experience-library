# Output Rules — 输出格式统一规范

> 本文定义所有 Agent 输出内容的格式规则。
> 不限于阶段报告，包括中间输出、日志、回复。

---

## 1. 格式总则

| 规则 | 说明 |
|------|------|
| Markdown | 所有输出必须是 Markdown 格式 |
| 中文为主 | 正文使用中文，关键术语保留英文 |
| 无 emoji | 禁止使用 emoji 表情符号 |
| 结论先行 | 每次输出以结论开头，解释在后 |
| 绝对路径 | 所有文件路径使用绝对路径 `D:/项目经验库/...` |

---

## 2. 标题层级规范

```
# 标题       — 仅用于阶段报告标题（1 级）
## 章节      — 报告内主要章节（2 级）
### 小节     — 章节内细分（3 级）
#### 条目    — 具体条目说明（4 级）
```

禁止跳级使用（如 # 后直接 ####）。

---

## 3. 引用规范

### 3.1 文件引用

```
格式：[类型] 路径:行号 — 描述

示例：
[报告] D:/项目经验库/reports/requirement/requirement_report.md:12 — 需求范围定义
[文件] D:/项目经验库/projects/DatasetConverterTool/overview.md:1 — 项目总览
```

### 3.2 结论引用

每个结论必须附带来源：

```
结论：{结论内容}
依据：{引用文件或数据}
```

---

## 4. 列表规范

### 4.1 无序列表

```
- {条目}
  - {子条目}
```

### 4.2 有序列表

```
1. {步骤 1}
2. {步骤 2}
```

### 4.3 清单列表

```
- [ ] {待办项}
- [x] {已完成项}
```

---

## 5. 表格规范

```markdown
| 列名 1 | 列名 2 | 列名 3 |
|--------|--------|--------|
| 内容   | 内容   | 内容   |
```

- 表头必须有分隔行
- 列对齐使用默认左对齐
- 长内容使用缩写，在表后注释

---

## 6. 代码块规范

### 6.1 文件路径

```
D:/项目经验库/workflow/workflow_stage.md
```

### 6.2 代码片段

```yaml
key: value
```

```markdown
# 标题
```

```text
纯文本内容
```

### 6.3 命令

```
bash
python D:/项目经验库/tools/build_index.py
```

---

## 7. 警告与提示规范

```markdown
> 注意：{注意事项}

> 警告：{严重警告}

> 信息：{补充信息}
```

---

## 8. 错误与退回报告格式

退回时必须使用以下格式生成 `failure_report.md`：

```markdown
# Failure Report

## Metadata
- Stage: {退回阶段}
- Target Stage: {退回目标阶段}
- Agent: {当前 Agent}
- Timestamp: {ISO 8601}

## Failure Reason
{具体退回原因}

## Violated Rules
- {workflow_rules.md:xx} — {违规说明}
- {workflow_checklist.md:xx} — {未通过项}

## Required Fix
{上游需要修正的具体内容}

## Evidence
{引用相关文件或数据作为证据}
```

---

## 9. 输出长度规范

| 输出类型 | 建议长度 |
|---------|---------|
| 阶段报告 | 不限，但每个章节不超过 200 行 |
| 中间回复 | 不超过 20 行 |
| 错误报告 | 不超过 30 行 |
| Checklist 结果 | 逐项列出，不合并 |

---

## 10. 禁止行为

| 行为 | 说明 |
|------|------|
| 禁止虚构 | 不得输出不存在文件或虚假数据 |
| 禁止猜测 | 无依据的结论必须标注 `[需确认]` |
| 禁止跳步 | 不得跳过 Checklist 中的检查项 |
| 禁止覆盖 | 不得覆盖未读取过的文件 |
| 禁止省略路径 | 文件引用必须包含完整绝对路径 |
