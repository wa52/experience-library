# 文件锁竞态条件

## 问题现象
快速双击启动多个实例时，第二个实例误判原实例已死，清理锁文件后自己启动。

## 影响项目
opencode-history-browser (standalone.js)

## 根因
`fs.open(lockFile, "wx")` 在第二次 open 时抛 EEXIST，但兜底的锁内容读取 + 健康检查可能因网络延迟误判。

## 解决方案
1. 锁文件内容包含完整 URL
2. 新实例读取锁文件 URL → 健康检查（`/api/health`）
3. 存活 → 打开已有浏览器 → 退出
4. 不存活 → 清理 → 自己启动

## 教训
- 文件锁需要精心设计兜底逻辑
- 竞态条件在多进程场景下发生概率远高于预期
- 锁文件内容和超时参数需要仔细权衡
