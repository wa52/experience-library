经验库存在两个并行的目录组织体系，造成混乱：

| 编号目录（原始规划） | 状态 | 实际内容所在 |
|-------------------|------|------------|
| `02_我的项目经验/` | **空目录** | `projects/` |
| `03_问题解决记录/` | **空目录** | `failure_database/` |
| `04_代码片段/` | **空目录** | `patterns/` |
| `05_数据集转换/` | **空目录** | 无任何内容 |
| `06_自动标注/` | **空目录** | 无任何内容 |
| `vector_db/` | **空目录** | 无任何内容 |
| `99_VectorDB/` | **空目录** | 无任何内容 |

### 1.2 实际有效内容分布

| 内容类型 | 位置 | 数量 |
|---------|------|------|
| 项目经验 | `projects/` | 8 个项目（含结构化的 multi-md 文档） |

`knowledge-agent-mcp/knowledge_base/` 中另有 9 个分类的知识文档（基础知识、技术知识、AI 知识、项目经验、问题与 Bug、解决方案、代码案例、最佳实践、资料来源），这是 MCP 项目的知识库，与根目录的"经验库"是不同用途。

### 1.4 索引与实际情况不符

- `00_索引/README.md` 描述的目录结构与实际不符（引用了已不存在的编号目录）

- `HALCON_INDEX.md` 和 `PROJECT_INDEX.md` 根级索引存在但路径混乱

## 3. 需求定义

### 3.1 核心原则
1. **不删内容**：只删除空目录，不删除任何有内容的文件
2. **不改路径**：现有文件不移位，避免破坏外部引用
3. **更新索引**：让 README 和索引文件反映真实结构
4. **统一术语**：全库使用一致的分类命名

### 3.2 具体需求

| # | 需求 | 验收标准 |
|---|------|---------|
| R1 | 删除 6 个空目录（02~06, vector_db, 99_VectorDB） | 目录消失，无文件丢失 |
| R2 | 重写根 README，反映真实结构 | README 描述与磁盘一致 |
| R3 | 更新 `00_索引/README.md` 和索引文件 | 索引路径正确 |
| R4 | 清理 `reports/` 中无关的工作流报告（保留目录结构存档） | 明确标注用途 |
| R5 | `GLOBAL_RULES.md` 更新 | 规则与当前结构一致 |
