# GLOBAL RULES — 全局项目经验库规则

> 以下规则对所有使用本经验库的 AI 编码助手（Codex、OpenCode、Claude Code 等）具有约束力。
> 经验库路径：D:/项目经验库
> 规则版本：v2.2

---

## 规则 0：OpenCode 多路径检索门禁（强制）

OpenCode、Codex、Claude Code 或任何 AI 助手在回答经验库相关问题时，禁止只命中一个文件就开始总结。必须先完成多路径检索，再输出结论。

本库只保存提炼后的经验，不保存原始资料、手册、官方例程、图片、模型、训练集或第三方源码。检索本库时只查经验类目录。

### 0.1 最低检索范围

每次检索至少覆盖以下 5 条路径，除非用户明确指定只查某个单一路径：

| 检索层级 | 必查路径 | 目的 |
|---|---|---|
| 总入口 | `00_索引/README.md`、`README.md` | 确认目录结构、固定入口、搜索策略 |
| 项目经验 | `00_索引/项目经验索引.md`、`projects/` | 找类似项目、架构、踩坑、验收 |
| 问题与代码 | `failure_database/`、`patterns/`、`domains/`、`tools/` | 找问题修复、可复用代码、领域总结 |

### 0.2 禁止偷懒规则

- 禁止只读第一个命中文件就总结。
- 禁止只查根目录 README 就回答技术问题。
- 禁止检索或引用本库外的原始资料作为经验库结论。
- 禁止把原始资料复制回经验库。
- 禁止只查单个目录就总结。
- 禁止把“没有搜索到”当结论，除非已经覆盖最低检索范围并列出检索词。

### 0.3 必须输出检索证据

回答前必须列出“检索证据”，至少包含：

```text
检索词：...
已查路径：
- 00_索引/README.md：命中/未命中
- 00_索引/项目经验索引.md / projects：命中/未命中
- failure_database / patterns / domains：命中/未命中
采用结果：项目经验 / 问题记录 / 模式 / 领域总结 / 未找到
```

### 0.4 推荐检索命令

```powershell
rg -n "关键词1|关键词2|算子名|文件名" D:\项目经验库\00_索引 D:\项目经验库\README.md
rg -n "关键词1|关键词2|算子名|文件名" D:\项目经验库\projects D:\项目经验库\failure_database D:\项目经验库\patterns D:\项目经验库\domains D:\项目经验库\tools
```

### 0.5 视觉开发问题的扩展关键词

视觉开发问题必须同时搜索中文词、英文词、HALCON 算子名和文件名线索。例如：

- 模板匹配：`模板匹配|template matching|shape_model|find_shape_model|create_shape_model|ncc_model`
- OCR：`OCR|read_ocr|do_ocr|deep_ocr|text recognition`
- 异常检测：`异常检测|anomaly|anomaly detection|surface inspection`
- 目标检测：`目标检测|object_detection|object detection|detect object`
- 数据集：`dataset.hdict|hdict|数据集|dataset|HALCON 数据集`
- 相机采集：`相机采集|framegrabber|grab_image|open_framegrabber|acquisition`

### 0.6 资料边界规范

经验库只记录经过项目验证或人工提炼后的经验。开发过程中必须遵守以下规则：

- 禁止把官方示例、手册、图片、模型、训练数据或第三方源码放入经验库。
- 禁止用原始资料替代项目经验、Bug 根因、可复用模式或领域总结。
- 如果从资料中得到可复用结论，只能把提炼后的结论写入 `projects/`、`failure_database/`、`patterns/` 或 `domains/`。
- 经验条目应说明适用场景、已验证项目、风险和下次规则，不记录资料全文。

## 规则 1：任务前必须检查项目配置文件

接到任何开发、修改、修复、重构任务前，必须先检查当前项目是否存在以下文件：

### 1.1 .ai/project_rules.md
如果存在，**必须优先读取**其中的项目专属规则。项目规则可以覆盖全局规则的某些部分。

### 1.2 .ai/experience_link.md
如果存在，**必须读取**其中的经验库路径链接。链接可以指向默认经验库或其他自定义路径。

### 1.3 默认路径
如果不存在 `.ai/experience_link.md`，默认使用以下经验库路径：

```
D:/项目经验库
```

### 检查流程伪代码
```python
if exists(".ai/project_rules.md"):
    apply(read(".ai/project_rules.md"))

if exists(".ai/experience_link.md"):
    library_path = extract_path(read(".ai/experience_link.md"))
else:
    library_path = "D:/项目经验库"

search_experience(library_path, task_keywords)
```

## 规则 2：修改代码前必须搜索经验库

在修改任何代码之前，必须按以下优先级搜索经验库：

### 搜索路径（按优先级）
| 优先级 | 路径 | 搜索目标 |
|--------|------|---------|
| 1 | `failure_database/` | 是否有完全相同的失败案例或解决方案 |
| 2 | `projects/` | 是否有类似项目的经验记录（decisions.md / lessons.md / bugs.md） |
| 3 | `patterns/` | 是否有匹配的架构模式或最佳实践 |
| 4 | `domains/` | 是否包含当前领域的技术总结 |

### 搜索工具
```bash
python <经验库路径>/tools/search_experience.py "关键词1 关键词2"
```

### 输出要求
搜索后必须在「参考经验摘要」中包含搜索记录：

```
### 历史经验搜索
- failure_database/：找到 X 条匹配 / 未找到匹配
- projects/：找到 X 个相关项目 / 未找到
- patterns/：找到 X 个匹配模式 / 未找到
- domains/：找到 X 个相关领域 / 未找到
- 复用决策：采用了 [具体方案] / 未采用（理由）
```

## 规则 3：发现相似问题必须优先复用

如果经验库中存在与当前任务相似的问题或方案，必须按以下规则处理：

### 复用优先级
| 来源 | 匹配条件 | 处理方式 |
|------|---------|---------|
| failure_database | 完全相同或高度相似 | **必须直接采用**已验证的解决方案，禁止重新实现 |
| patterns | 场景匹配 | **必须采用**推荐架构，不允许另起炉灶 |
| bugs | 现象匹配 | **必须参考**解决方案，禁止重复踩坑 |
| projects/decisions | 技术选型匹配 | **优先复用**已验证的技术决策 |

### 禁止行为
- ❌ 忽略历史经验直接重新设计
- ❌ 重新实现已经验证成功的方案
- ❌ 走经验库中已有记录的失败路径
- ❌ 在已有成熟 Pattern 的情况下另搞一套架构

## 规则 5：修改范围按风险分层，修改后必须说明

### 修改限制
- 默认限制：单次任务最多同时修改 3 个**既有文件**。
- 新建豁免：创建全新项目经验包时，可一次创建完整 9 个标准文件（overview/architecture/decisions/lessons/bugs/checklist/anti_patterns/reusable_parts/next_time_rules），但不得顺带修改无关既有文件。
- 批量新增独立经验条目时，可一次新增最多 9 个新文件；如需修改已有文件，既有文件仍受 3 个限制。
- 自动生成文件（如运行 `tools/build_index.py` 更新 `index/`）不计入上述文件数量限制，但必须在修改说明中列出。
- 如果需要修改超过 3 个既有文件，必须分阶段进行。
- 每阶段完成后等待用户确认，再进入下一阶段。

### 修改说明格式
每次修改后必须输出以下内容：

```
## 修改说明
### 修改文件
1. `文件路径` — 修改了什么，为什么修改（引用经验库依据）
2. `文件路径` — 修改了什么，为什么修改

### 改动摘要
- 新增代码：XX 行
- 删除代码：XX 行
- 修改代码：XX 行

### 测试方式
- 手动测试步骤
- 自动化测试命令
- 验证指标

### 回退方式
- 如果需要回退，执行的 git 命令
```

## 规则 6：同一问题连续失败 3 次必须停止

如果对同一个问题连续尝试 3 次仍未解决，AI **必须立即停止**继续尝试。

### 停止前的确认
在认定"失败"之前，必须先确认已经按规则 2 搜索过所有经验库路径。如果发现之前漏搜了，必须先补搜。

### 禁止行为
- ❌ 继续改代码碰运气
- ❌ 删除或绕过测试让结果看起来"通过"
- ❌ 用 `# TODO` / `pass` / `NotImplementedError` 占位掩饰问题
- ❌ 降低验收标准来凑合
- ❌ 未搜索经验库就擅自尝试新方案

---

## 规则 8：任务完成后必须更新经验记录

每次任务完成后，AI 必须将经验回写到经验库。

### 完成门禁
凡是项目已经跑通、Bug 已修复、功能已交付、打包已完成、测试已通过或用户明确说“项目弄好后”，都必须在最终回复前完成经验库回写。

如果没有完成以下动作，不允许声明“完成”：

1. 将本次新增经验写入 `D:/项目经验库` 的对应目录。
2. 项目类经验更新 `projects/<项目名>/`，Bug 类经验更新 `failure_database/`，可复用方案更新 `patterns/`，领域知识更新 `domains/`。
3. 运行 `python D:/项目经验库/tools/build_index.py` 重建索引。
4. 在最终回复中列出已更新的经验库文件和验证命令。

如果当前环境无法写入 `D:/项目经验库`，必须在最终回复中明确说明“经验库未更新”和阻塞原因，不能假装已回写。

### 回写规则
| 情况 | 写入位置 | 内容要求 | 时限 |
|------|---------|---------|------|
| 完成了新项目 | `projects/<项目名>/` | 创建 9 个标准文件 | 项目交付时 |
| 修复了 Bug | `failure_database/` | 记录现象、根因、方案 | 任务完成前 |
| 发现了可复用模式 | `patterns/` | 记录场景、架构、流程、坑点 | 任务完成前 |
| 发现了领域特定知识 | `domains/` | 记录技术要点、最佳实践 | 当天 |
| 完成了功能里程碑 | `projects/<项目名>/` | 更新 checklist.md | 里程碑达成时 |

### 项目标准文件（9 个）
```
projects/<项目名>/
├── overview.md         # 项目总览（一句话、定位、技术栈、功能、状态）
├── architecture.md     # 架构设计（分层图、交互流程、线程模型）
├── decisions.md        # 关键决策（ADR：背景、方案、结论、代价）
├── lessons.md          # 经验教训（技术 + 项目管理）
├── bugs.md             # Bug 记录（现象、根因、修复、参考）
├── checklist.md        # 验收清单（功能、性能、兼容性、安全）
├── anti_patterns.md    # 反模式（症状、正确做法）
├── reusable_parts.md   # 可复用模块（提取位置、用途、核心代码）
└── next_time_rules.md  # 下次规则（架构/流程/测试/待改进）
```

### 禁止写入的内容
- ❌ 完整的源码文件或大段代码
- ❌ 第三方库的完整文档
- ❌ 个人敏感信息（API Key、密码等）
- ❌ 与项目无关的内容

### 允许写入的内容
- ✅ 项目目标与定位
- ✅ 架构决策与技术选型
- ✅ Bug 原因与解决方案
- ✅ 验收标准与测试方法
- ✅ 反模式与改进建议
- ✅ 下次开发的注意事项

## 规则 9：更新对应目录

当项目达到以下里程碑时，必须同步更新经验库中的对应目录：

| 里程碑 | 必须更新的目录 |
|--------|--------------|
| 项目达到可运行版本 | `projects/<项目名>/`（创建/更新 9 个文件） |
| 功能开发完成 | `projects/<项目名>/checklist.md` |
| Bug 修复完成 | `failure_database/`（写入修复方案） |
| 重构完成 | `patterns/`（如果有新模式）/ `projects/<项目名>/architecture.md` |
| 发现架构缺陷 | `projects/<项目名>/anti_patterns.md` |
| 发现可复用模块 | `projects/<项目名>/reusable_parts.md` |

### 索引维护
每次更新后，运行以下命令重建索引：

```bash
python <经验库路径>/tools/build_index.py
```

## 规则 10：内容规范 — 不复制源码，只记录经验

经验库中所有文件必须遵守以下内容规范。

### 允许记录的内容
- **项目目标**：项目要解决什么问题，面向什么场景
- **架构决策**：为什么选择这个方案，其他方案的优缺点
- **Bug 原因**：现象、根因分析、修复方案（不贴完整源码）
- **解决方案**：关键步骤、核心代码片段（不超过 30 行）
- **验收标准**：功能、性能、兼容性、安全 Checklist
- **反模式**：错误做法、症状、正确做法
- **下次规则**：下次开发应该注意什么

### 禁止记录的内容
- ❌ 完整的项目源码文件
- ❌ 第三方库的文档或 API 参考
- ❌ 原始资料、手册、官方例程、图片、模型、训练集
- ❌ 个人敏感信息（API Key、Token、密码、密钥）
- ❌ 与当前项目无关的通用教程
- ❌ 超过 30 行的连续代码块

### 代码片段规范
当需要贴代码时：
- 只贴关键逻辑（不超过 30 行）
- 必须附带上下文说明
- 必须标注文件位置
- 使用正确的语言标识符（```python / ```javascript / ```csharp）

### 引用规范
- 引用经验库其他文件时，使用相对路径：`patterns/pyqt5_roi_tool.md`
- 引用外部资源时，提供可访问的 URL
- 不允许编造引用来源

## 工作流程速查

```
接到任务
  │
  ├─→ 规则 1：检查 .ai/project_rules.md + .ai/experience_link.md
  ├─→ 规则 2：搜索经验库 failure_database/ → projects/ → patterns/ → domains/
  ├─→ 规则 3：发现相似问题 → 优先复用，禁止重新实现
  ├─→ 规则 4：输出参考经验摘要 → 制定修改计划 → 用户确认
  ├─→ 规则 5：分阶段修改（≤3 文件/次）→ 输出修改说明
  ├─→ 规则 6：失败 → 最多 3 次 → 必须停止
  ├─→ 规则 7：生成 .ai/failure_report.md
  ├─→ 规则 8：任务完成 → 更新经验库记录
  ├─→ 规则 9：里程碑达成 → 同步更新对应目录
  └─→ 规则 10：不复制源码，只记录经验
```
