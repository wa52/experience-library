# GLOBAL RULES - 经验库使用规则

> 目标：让 AI 编码助手在开发前快速吸收历史经验，并把有价值的新经验沉淀回来。
> 经验库路径：由 `.ai/experience_link.md` 指定，默认 `D:/项目经验库`。

## 1. 任务前快速检索

处理开发、修复、重构或架构任务前，先读取当前项目的 `.ai/project_rules.md`（如果存在）和 `.ai/experience_link.md`（如果存在），然后调用经验检索：

```powershell
python <经验库路径>/tools/search_experience.py "关键词1 关键词2"
```

优先搜索以下权威内容目录：

```text
failure_database/
projects/
patterns/
domains/
```

默认先返回 Top 3-5 条候选，不要求读取所有索引页或所有命中文档。只有候选明显相关时，才展开读取全文。

关键词应覆盖用户描述、错误信息、技术名、版本、算子名和文件名。视觉问题同时搜索中文、英文和相关算子名。

## 2. 经验是参考，不是命令

命中经验后必须检查技术版本、平台、依赖、线程模型、输入输出和验证条件：

- 条件一致：优先复用，并说明采用了什么。
- 条件部分一致：只复用适用部分，并说明调整点。
- 条件不一致或经验过时：允许采用新方案，并记录未复用的原因。
- 没有可靠命中：直接设计方案，不为了满足规则强行套用历史方案。

## 3. 开发与验证

```text
任务 -> 快速检索经验 -> 判断适用性 -> 最小改动 -> 测试验证 -> 按需写回经验
```

正常开发不要求先输出长篇检索报告。需要向用户说明时，简要列出实际采用的经验和未采用的关键原因即可。

## 4. 写回经验

任务完成且产生可复用结论时，写入对应目录：

| 内容 | 位置 |
|---|---|
| 项目背景、决策、教训 | `projects/<项目名>/` |
| 跨项目 Bug 和根因 | `failure_database/` |
| 可复用架构或流程 | `patterns/` |
| 技术领域总结 | `domains/` |

写入后运行：

```powershell
python <经验库路径>/tools/build_index.py
```

索引文件是派生导航，不是知识源，也不是 Agent 检索门禁。内容权威性以四个内容目录中的原文为准。

## 5. 内容和安全边界

- 只记录提炼后的经验，不复制完整源码、第三方文档、模型、训练集或原始资料。
- 不写入 API Key、Token、密码、个人隐私或本机凭据。
- 引用经验库文件时使用相对路径。
- MCP 服务只提供知识读取和检索，不执行项目命令，不直接修改经验文档。

## 6. 历史目录

`archive/` 只保存历史结构、迁移记录和不再参与主流程的内容。Agent 默认不搜索归档目录，除非用户明确要求追溯历史。
