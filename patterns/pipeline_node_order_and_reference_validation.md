# 视觉检测流水线的节点顺序与输入引用校验（VisionMaster 式模块化）

## 适用场景

C# 视觉检测程序把检测流程拆成可增删排序的节点（检测/条件判断/显示/保存/IO 输出），节点按列表顺序执行，后节点可引用前节点的输出图或结果字段。适用于 SpeakerVisionInspection 这类方案(Recipe)驱动、节点可自由编排的架构。

## 关键结论

- 节点在 `recipe.Nodes` 列表中的顺序 = 流水线执行顺序 = "谁能引用谁"：只有排在前面的节点才是合法上游。UI 的"上游节点下拉"应按同一口径生成（取列表中当前节点之前的前缀）。
- 流水线在每次「开始生产」时重建实例，因此编辑期增删/排序只影响下次启动；编辑接口统一用"将停止当前服务"确认即可，无需热更新。
- **"输入输出对不上"必须在两层都输出日志**：
  1. 构建期（Pipeline 构造完节点后）静态校验：引用节点不存在 / 引用了自己或下游节点 / 多个显示节点只保留最后一个。格式统一 `[校验] {节点}: ...`，只记日志不阻断生产。
  2. 运行期兜底：Display/SaveImage 取不到来源图、CameraIo 取不到来源结果时各记一条 `[节点类型] {名}: ...未找到...`，不允许静默返回空值。
- **日志通道陷阱**：节点工厂（Factory）创建节点时容易漏传 logger（只有特殊分支的节点有日志，其余节点日志是空操作）。解法：节点类暴露可写 `Log` 属性，Pipeline 构造时按类型统一注入，工厂签名保持稳定不破坏测试。
- 多个显示节点时"最后一个生效"，前一个的输出 Mat 必须先 Dispose 再覆盖，否则每次检测泄漏一张克隆图。

## 推荐配置模式

```text
recipe.Nodes 顺序:  [检测模型] -> [条件检测(引用模型)] -> [相机IO通信(引用条件检测)] -> [图像显示/输出图像(引用任意上游)]
UI: 选中节点 -> Inspector 提供 上移/下移/删除；添加模块菜单显示中文名（图像显示 (Display) 等）
校验日志: [校验] {节点}: 来源 '{X}' 不存在 | 不是上游节点（顺序错误） | 实际显示最后一个: {X}
运行日志: [Display]/[SaveImage]/[CameraIo] {名}: 图像来源未找到: {X} ...
```

## 禁止做法

- 不要在 UI 上允许把"来源"配置成下游节点而不给任何提示——这是运行期取不到图像的头号原因。
- 不要让工厂创建的节点丢 logger（静默失败最难排查）。
- 不要在校验失配时直接抛异常阻断生产（现场要求先能跑，问题通过日志暴露）；也不要静默吞掉——两层日志缺一不可。

## 验证清单

- 引用不存在的节点 → 启动/构建时出现 `[校验] ... 不存在`。
- 把显示节点移到其来源节点之前 → 出现 `[校验] ... 顺序错误`。
- 添加两个显示节点 → 出现"实际显示最后一个"提示，且最终 DisplayImage 为最后一个节点输出、无 Mat 泄漏。
- 单元测试覆盖：不存在 / 顺序错 / 多显示提示 / 正常上游不误报 / SaveImage 运行期日志 / 最后生效。
