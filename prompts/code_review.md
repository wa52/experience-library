# Code Review 提示词模板

> 用于指导 AI 进行代码审查的提示词模板。

## 模板

```
## 审查范围
{scope_description}

## 审查重点
- [ ] 功能正确性
- [ ] 性能问题
- [ ] 安全漏洞
- [ ] 代码风格
- [ ] 异常处理
- [ ] 资源释放
- [ ] 线程安全
- [ ] 兼容性

## 相关文件
{file_list}

## 经验库参考
审查时请参考：
- {pattern_reference} — 架构是否符合推荐模式
- {bug_reference} — 是否引入了已知 Bug 类型的代码

## 审查输出格式
对每个文件列出：
1. 问题位置（文件名:行号）
2. 问题类型（Bug / 性能 / 风格 / 安全）
3. 问题描述
4. 建议修复方案
5. 优先级（P0 阻塞 / P1 重要 / P2 建议）

## 审查原则
- 不要求完美，只关注实际问题
- 提出改进建议时附带理由
- 对 P0/P1 问题给出具体修复代码
```

## 审查检查清单

### 功能正确性
- [ ] 所有输入参数是否校验
- [ ] 边界条件是否处理（空列表、None、0 等）
- [ ] 返回值是否在所有路径上都有定义

### 性能
- [ ] 是否有不必要的循环或重复计算
- [ ] 大文件/大数据操作是否分块处理
- [ ] 是否缓存了可复用的计算结果

### 安全
- [ ] API Key / 密码是否硬编码
- [ ] 用户输入是否经过验证或转义
- [ ] 文件路径遍历攻击防护

### 资源
- [ ] 文件/网络连接是否及时关闭
- [ ] 数据库连接是否归还连接池
- [ ] 大对象是否及时释放

### 线程安全
- [ ] 共享数据是否有锁保护
- [ ] UI 更新是否在主线程
- [ ] Queue 是否使用正确的 get/put 方法
