# Node.js 内嵌 Web 应用开发 — 领域经验

## 适用场景
构建一个 Node.js 进程 + 浏览器 UI 的本地工具，用户通过浏览器访问本地服务。

## 架构模式

### 通信方式选择

| 方式 | 优势 | 劣势 | 推荐场景 |
|------|------|------|---------|
| HTTP + 轮询 | 简单，Node.js 内置 http 模块 | 延迟 1-2s | 本地工具 |
| WebSocket | 实时 | 需要 ws 库 | 实时协作 |
| Unix Socket | 高性能 | 平台差异 | 同一进程 |

### 端口管理
- 从固定端口开始尝试，失败则 +1，范围 20 个
- 只在 `127.0.0.1` 监听，不暴露到局域网
- 端口号硬编码或通过环境变量配置

### 认证
- 随机 Token（18+ 字节）通过 URL 参数传递
- 双重验证：Header + URL 参数
- Token 持久化到文件/配置，进程重启后复用

## 关键技术决策

### 前后端交互
1. **API 路径规则**：`/api/resource` 前缀区分 API 和静态文件
2. **JSON 响应格式**：统一 `{ ok: true, data }` 或 `{ error: "message" }`
3. **错误处理**：服务端返回 status code + JSON error body
4. **路径脱敏**：所有 URL 在日志中必须 redact token

### 进程管理
1. **子进程**：`spawn` 而非 `exec`，避免缓冲溢出
2. **隐藏窗口**：Windows 下 `windowsHide: true`
3. **生命周期**：父进程退出时，子进程通过 `child.kill()` 和 `process.on("exit")` 清理
4. **进程锁**：文件锁 + 健康检查防重复启动

### 前端实时性
1. **轮询 vs 推送**：工具类应用轮询足够，1-2s 间隔
2. **变化检测**：用签名（signature）判断数据是否变化，避免无效渲染
3. **心跳**：10-15s 间隔检测浏览器是否存活

## 推荐工具链
- **构建**：无需构建工具，纯原生 HTML/CSS/JS
- **打包**：单个 Node.js 脚本发布，零依赖（除 SDK）
- **日志**：JSON 格式追加写入文件，支持按级别过滤
- **调试**：文件日志 + 浏览器控制台

## 常见坑点
1. **端口竞态**：并发检测端口可用性时冲突，用 listen + 回退而非先检测再 listen
2. **Token 安全**：URL 中的 Token 可能在 Referer 头、历史记录、日志中泄漏
3. **子进程僵尸**：父进程崩溃时子进程变成孤儿，用进程组或 PPID 检测
4. **浏览器缓存**：静态文件必须设置 `cache-control: no-store`
5. **路径后缀**：API 路径和文件路径不要冲突（用 /api/ 前缀隔离）
6. **Windows 路径**：`cmd /c` vs `cmd /k`，`.cmd` vs `.ps1` 行为差异
7. **文件锁**：Windows 下防病毒软件可能锁定临时文件
